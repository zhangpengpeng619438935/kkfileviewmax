# 文件预览服务 · 业务系统接入指南

> 面向各业务系统（OA / PLM / MES / 知识库 / 文控 …）的开发人员。看完这份文档，30 分钟内可以完成联调。
> 接口参考手册见 `API调用文档.md`，运维见 `运维手册.md`。

## 一、服务现状

| 项 | 值 |
|----|----|
| 服务地址 | `http://127.0.0.1:9012`（内网，无需 HTTPS） |
| API 基址 | `http://127.0.0.1:9012/api/v1` |
| 统计看板 | `http://127.0.0.1:9012/`（含「服务健康」页，可看四个容器实时状态） |
| 当前状态 | 已部署并实测通过（60 并发 / 秒，P95 58 ms） |
| 支持格式 | Office（doc/docx/xls/xlsx/ppt/pptx/wps/et/dps）、PDF、OFD、**图片（png / jpg / jpeg / bmp / gif，实测通过；svg 由网关矢量渲染）**、文本（**md**、txt、xml、json、log、各类代码文件）、CAD（dwg/dxf/dwf/dwt）、压缩包（zip/rar/7z/tar）、音视频、邮件（eml/msg）、xmind/bpmn/drawio |
| 已开通账号 | `kk-demo`（演示）、`oa`、`plm`、`kb`，每个系统默认 60 QPS |

**接入总量控制**：全局 120 QPS，单系统 60 QPS，单工号 20 QPS。超出返回 429，需要退避重试。

## 二、接入四步

```
1. 向管理员申请 appId + appSecret（已有系统可跳过）
2. 用 appId/appSecret 换取 accessToken（有效期 2 小时，记得缓存复用）
3. 携带 token + 工号调用 /preview/url 拿到预览地址
4. 前端用 iframe 或 window.open 打开该地址
```

### 第 1 步：申请账号

**推荐用看板操作**（不用敲命令）：打开 http://127.0.0.1:9012/ → 顶部「系统账号」页 → 输入管理员令牌登录 → 填系统标识和名称，**密钥留空会自动生成强口令** → 点「生成 / 保存」。页面下方会列出所有已接入系统及其密钥，可显示/复制/重置/停用/删除。

也可以用命令行：

```bash
curl -X POST http://127.0.0.1:9012/api/v1/admin/app \
  -H 'X-Admin-Token: change-me-admin-token' -H 'Content-Type: application/json' \
  -d '{"appId":"mes","appName":"MES 系统","qpsLimit":30,"ipWhitelist":"127.0.0.1,127.0.0.1"}'
# 返回: {"data":{"appId":"mes","appSecret":"kk-xxxx...","generated":true,"action":"created"}}
```

- `appSecret` 留空 → 自动生成 `kk-` 开头的强随机密钥（已存在的账号则保持原密钥不变）
- `qpsLimit`：该系统每秒配额，按实际并发量给（默认 60）
- `ipWhitelist`：**留空 = 不限制来源 IP（默认）**。只有在需要收紧时才填业务服务器 IP，管理员随时可在看板改
- 管理员令牌在部署目录 `.env` 的 `ADMIN_TOKEN`（当前默认 `change-me-admin-token`，**建议尽快修改**）

### 第 2 步：换取令牌

```bash
curl -X POST http://127.0.0.1:9012/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"appId":"kk-demo","appSecret":"your-app-secret"}'
```

```json
{"code":0,"msg":"ok","data":{"accessToken":"eyJhcHAiOiJray1kZW1vIiwiZXhwIjoxNzky...","expiresIn":7200,"qpsLimit":60}}
```

> 令牌 2 小时有效。**请在服务端缓存并在到期前 5 分钟刷新**，不要每次预览都重新换取（浪费配额且慢）。

### 第 3 步：申请预览地址

```bash
curl -X POST http://127.0.0.1:9012/api/v1/preview/url \
  -H 'X-App-Id: kk-demo' \
  -H 'Authorization: Bearer <accessToken>' \
  -H 'Content-Type: application/json' \
  -d '{
        "fileUrl": "http://127.0.0.1:8899/hello.txt",
        "empNo": "EMP0001",
        "empName": "张三",
        "dept": "示例事业部",
        "fileName": "测试报告.docx"
      }'
```

**请求参数**

| 字段 | 必填 | 说明 |
|------|------|------|
| fileUrl | 是 | 文件的 HTTP 下载地址，域名需在服务白名单内（找管理员加） |
| empNo | 是 | 当前登录人工号，写入审计日志 |
| empName | 否 | 姓名（建议传，审计更好追溯） |
| dept | 否 | 部门 |
| fileName | 否 | 展示用文件名，不传则自动从 URL 解析 |

**返回①：可以直接预览**

```json
{"code":0,"data":{"status":"ready","fileKey":"a838...","fileName":"hello.txt",
 "fileType":"txt","previewUrl":"http://127.0.0.1:9012/api/v1/preview/page?token=...","expiresIn":600}}
```

> **默认会同步等待**：首次预览时接口会等转码完成（最多 30 秒）再返回，**直接给 `previewUrl`**，调用方不需要自己轮询。实测 xlsx / docx / pptx 约 1 秒即可拿到地址。

只有超过 30 秒还没转完时，才返回"转码中"：

```json
{"code":0,"data":{"status":"converting","taskId":"6dc24995...","fileName":"real.docx",
 "pollUrl":"http://127.0.0.1:9012/api/v1/preview/status?taskId=6dc24995...",
 "tip":"文件转码超过 30 秒仍未完成, 请轮询 pollUrl ..."}}
```

可以用 `wait` / `waitSeconds` 控制等待行为：

```json
{"fileUrl":"...","empNo":"EMP0001","wait":true,"waitSeconds":60}
```

- `wait: true`（默认）——等转码完成再返回，拿到就是预览地址，代码最简单
- `wait: false`——立即返回，自己轮询 `pollUrl`，适合批量预热或超大文件

拿到地址后直接打开即可（见第四节）。

### 第 4 步：前端展示

```javascript
// 方式一：iframe 嵌入（推荐，用户体验好）
<iframe src={previewUrl} width="100%" height="800px" frameborder="0" />

// 方式二：新窗口打开
window.open(previewUrl);
```

预览地址 10 分钟内有效，过期需重新调用第 3 步。

## 三·五、内嵌预览（iframe）详解

**可以内嵌，直接把 `previewUrl` 放进 iframe 就行。** 服务侧已经为此做了适配：

| 适配项 | 说明 |
|--------|------|
| 令牌随 URL 传递 | 预览地址跳转后形如 `/kk/onlinePreview?url=xxx&kkt=<令牌>`，**不依赖 Cookie**，因此跨域 iframe 里不会被浏览器因第三方 Cookie 策略拦截 |
| 未设置 `X-Frame-Options` / CSP | 网关代理时也会过滤掉这两个头，浏览器不会阻止嵌入 |
| iframe 内子资源放行 | 预览页里的 js/css/图片、文件流请求都会正常放行（通过 URL 令牌或 Referer 校验） |
| 防盗链仍在 | 不经过授权直接拼 URL 访问 `/kk/onlinePreview` 会返回 401 |

**推荐用法**

```javascript
// 后端拿到 previewUrl 后
function embedPreview(url, container, height = 800) {
  container.innerHTML = '';
  const iframe = document.createElement('iframe');
  iframe.src = url;
  iframe.width = '100%';
  iframe.height = String(height);
  iframe.style.border = '0';
  iframe.allowFullscreen = true;
  container.appendChild(iframe);
}
```

或直接用 HTML：

```html
<iframe src="{previewUrl}" width="100%" height="800px" frameborder="0" allowfullscreen></iframe>
```

完整封装见 `docs/examples/preview.js` 的 `embedPreview()`。

**三个注意点**

1. **HTTPS 页面不能嵌入 HTTP 内容**（浏览器混合内容策略）。如果业务系统是 `https`，预览服务是 `http://127.0.0.1:9012`，iframe 会被浏览器直接拦掉。解决办法二选一：
   - 给预览服务加 HTTPS（在前面挂 Nginx 反代 + 内网证书）
   - 业务系统在内网用 HTTP 访问
2. **预览地址 10 分钟有效**：页面停留过久再刷新 iframe 会失效，重新调一次第 3 步即可；也可在打开前现取地址。
3. **iframe 高度**：预览页是自适应的，建议给 800px 以上；工具栏、翻页都在 iframe 内部完成，业务系统无需处理。

**是否需要限制"哪些域名能内嵌"**：默认不限制。管理员如需收紧，在 `.env` 配 `EMBED_ALLOWED_HOSTS=oa.corp.com,plm.corp.com`，然后 `docker compose up -d kk-gateway`——不在列表里的来源访问预览入口会被拒绝（业务系统先调自己后端拿地址再嵌入的模式不受影响）。

## 三、鉴权规则（务必遵守）

| 项 | 要求 |
|----|------|
| `X-App-Id` | 所有接口必传请求头 |
| `Authorization` | `Bearer <accessToken>` |
| 工号 `empNo` | **业务接口必填**，格式 3–32 位字母数字下划线，用于审计追溯 |
| 来源 IP | **默认不限制**。管理员如需收紧，在「系统账号」页给该 appId 填 IP 白名单（逗号分隔），保存即生效 |
| 文件地址 | **默认不限制来源域名**。任何 http/https 文件地址都可预览；管理员如需收紧，在 `.env` 的 `TRUST_HOSTS` 填域名 |
| 限流 | 全局 120 / 单系统 60 / 单工号 20 QPS，超限 429 |

**重要**：token 与 appSecret 属于系统凭证，**请放在服务端**，不要写在前端 JS 里。正确做法是：前端请求自己的后端 → 后端携带凭证调用预览服务 → 把 previewUrl 返回给前端。

## 四、首次预览较慢的处理（Office 转码）

Office/CAD 文件首次预览需要转码（实测 docx 约 6 秒），之后走缓存秒开。两种处理方式：

### 方式 A：轮询状态（通用）

```
调 /preview/url 返回 converting → 每 3 秒调一次 pollUrl → status=ready
→ 再次调 /preview/url（此时返回 ready 与 previewUrl）→ 前端打开
```

```bash
curl -H 'X-App-Id: kk-demo' -H 'Authorization: Bearer <token>' \
  'http://127.0.0.1:9012/api/v1/preview/status?taskId=6dc24995...'
# {"code":0,"data":{"taskId":"...","status":"ready","fileName":"real.docx","previewUrl":"http://..."}}
```

### 方式 B：提前预热（推荐，用户体验最好）

在用户点击之前就把文件放进转码队列，用户打开时已是 ready：

```bash
curl -X POST http://127.0.0.1:9012/api/v1/preview/task \
  -H 'X-App-Id: kk-demo' -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"fileUrl":"http://127.0.0.1:8899/real.docx","empNo":"EMP0001"}'
```

典型用法：列表页加载时批量预热前 N 个文件；或夜间定时预热次日高频文件。

### Java（Spring Boot 项目）

```java
@Service
public class FilePreviewService {
    private static final String BASE = "http://127.0.0.1:9012";
    private final String appId = "mes";
    private final String appSecret = "你的密钥";
    private String token;
    private long tokenExpireAt;

    public String previewUrl(String fileUrl, String empNo, String empName) throws Exception {
        String body = String.format(
            "{\"fileUrl\":\"%s\",\"empNo\":\"%s\",\"empName\":\"%s\"}", fileUrl, empNo, empName);
        String json = post(BASE + "/api/v1/preview/url", body, true);
        // 解析 json 取 data.previewUrl；若 status=converting 则轮询 pollUrl
        return extract(json, "previewUrl");
    }
    // 完整实现(含 token 缓存、轮询、异常处理)见 docs/examples/KkFilePreviewClient.java
}
```

### JavaScript（Node / 浏览器后端）

```javascript
const BASE = 'http://127.0.0.1:9012';
let cached = { token: '', expireAt: 0 };

async function getToken(appId, appSecret) {
  if (cached.token && Date.now() < cached.expireAt - 300000) return cached.token;
  const r = await fetch(`${BASE}/api/v1/auth/token`, {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ appId, appSecret })
  }).then(r => r.json());
  cached = { token: r.data.accessToken, expireAt: Date.now() + r.data.expiresIn * 1000 };
  return cached.token;
}

async function previewUrl(fileUrl, empNo, empName) {
  const token = await getToken('kk-demo', 'your-app-secret');
  const r = await fetch(`${BASE}/api/v1/preview/url`, {
    method: 'POST',
    headers: { 'X-App-Id': 'kk-demo', 'Authorization': `Bearer ${token}`,
               'Content-Type': 'application/json' },
    body: JSON.stringify({ fileUrl, empNo, empName })
  }).then(r => r.json());
  return r.data;   // ready 时取 previewUrl，converting 时轮询 pollUrl
}
```

### Python

```python
import json, urllib.request

BASE = "http://127.0.0.1:9012"
APP_ID, SECRET = "kk-demo", "your-app-secret"

def call(path, payload=None, token=None):
    req = urllib.request.Request(BASE + path,
        data=json.dumps(payload).encode() if payload else None,
        headers={"Content-Type": "application/json",
                 "X-App-Id": APP_ID,
                 **({"Authorization": "Bearer " + token} if token else {})})
    return json.loads(urllib.request.urlopen(req, timeout=30).read())

token = call("/api/v1/auth/token", {"appId": APP_ID, "appSecret": SECRET})["data"]["accessToken"]
res = call("/api/v1/preview/url",
           {"fileUrl": "http://127.0.0.1:8899/real.docx",
            "empNo": "EMP0001", "empName": "张三"}, token)
print(res["data"].get("previewUrl") or res["data"]["pollUrl"])
```

## 六、错误码与排查

| code | 含义 | 处理 |
|------|------|------|
| 0 | 成功 | — |
| 400 | 参数缺失或工号格式不合法 | 检查 empNo（3–32 位字母数字下划线） |
| 401 | 令牌缺失/过期/不匹配；预览地址过期 | 重新换 token 或重新申请预览地址 |
| 403 | 文件来源域名不在白名单、IP 不在白名单、文件类型被禁 | 找管理员加白名单 |
| 404 | taskId 不存在 | 检查任务 ID |
| 429 | 超出限流配额 | 退避重试（建议 1s/2s/4s），或申请提高配额 |
| 500 | 服务内部错误 | 提供 `X-Request-Id` 响应头找管理员查日志 |
| 502 | 预览引擎不可达 | 服务侧故障，联系管理员 |

每次响应都带 `X-Request-Id` 响应头，排查问题时请一并提供。

## 九、常见故障：403「链接签名无效」

**现象**：预览页提示"该(xls)文件，系统暂不支持在线预览，具体原因如下：Server returned HTTP response code: 403 for URL: ..."

**根因**：文件名里含 `&`（例如 `11-初始过程研究（Cpk & Ppk）`），拼进 URL 的 query 参数时没转义。服务端把 `&` 当成参数分隔符，`path` 被截断成 `...（Cpk `，签名自然对不上。

**网关已做兜底**（2026-10-20 上线）：
1. 自动把参数值里的字面 `&` 编码（`urlFixed=true` 会告诉你被修正过）
2. 传给引擎时**再编码一层**（kkFileView 内部会对 URL 做规范化，会把 `%26` 还原成 `&`，必须抵消）
3. 转码前先探测文件能否下载，不可访问时接口直接报明确错误，而不是让用户看到模糊的"暂不支持"
4. 引擎若返回失败提示页，会提取具体原因写入任务状态（`/preview/status` 的 `errMsg`）

**但仍建议调用方修自己的链接生成逻辑**——用标准 URL 编码，一劳永逸：

```java
// Java
String url = base + "?path=" + URLEncoder.encode(filePath, StandardCharsets.UTF_8);
```
```javascript
// JS
const url = `${base}?path=${encodeURIComponent(filePath)}`;
```

这样 `urlFixed` 会是 `false`，链路最干净。

## 十、常见问题

| 问题 | 解答 |
|------|------|
| **支持 md 文档吗？** | 支持。md 与 txt/xml/json/log/代码文件一样走文本通道直接渲染（**按纯文本显示，不渲染 Markdown 排版**），无需转码、秒开 |
| **支持哪些图片格式？** | **png、jpg、jpeg、bmp、gif 全部支持**（实测通过，不转码、直接渲染、秒开）；**svg 也支持**（网关内嵌矢量渲染，放大不失真）。tif/tiff 走引擎的多页预览。**webp、heic 当前不支持**（引擎版本较早）——如果你们有 webp 需求，可按 svg 同样方式加上 |
| 图片预览有什么限制？ | 单文件上限 1GB（`MAX_FILE_SIZE_MB`，2026-11-03 起真正生效）；超大图片（数十 MB）首次加载取决于网络与浏览器解码，与预览服务无关 |
| **调用接口 8 秒还没返回数据？** | 接口本身是毫秒级返回的。如果觉得"没数据"，通常是拿到了 `converting`（转码中）而不是地址——现在接口**默认同步等待 30 秒**，直接返回地址；超过 30 秒才返回 converting。也可以用 `waitSeconds` 加大等待，或提前预热 |
| 预览地址能直接分享给别人吗？ | 有效期 10 分钟且绑定申请人工号，过期失效；但仍建议不要外传 |
| 一个文件每次都要重新转码吗？ | 不需要，转码结果有缓存，第二次起秒开 |
| 工号必须传真实工号吗？ | 是，用于审计追溯，也是"谁看了什么文件"的唯一依据 |
| 能预览本地磁盘文件吗？ | 不能直接传路径，需提供一个 HTTP 下载地址（内网文件服务器即可） |
| 大文件（>1GB）能预览吗？ | 会被拒绝（413「文件 N MB，超过 1024 MB 上限」）。库内最大 901MB 的培训视频，1GB 阈值为其留了余量 |
